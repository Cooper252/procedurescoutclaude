# Deployment plan (D-048)

Status: **prepared, not deployed.** Nothing is signed up or paid for yet.

## What runs where

| Piece | Where | Plan (checked 2026-11-08) | Monthly |
|---|---|---|---|
| Website (`apps/web`) | Render web service | 0.5c-512mb | $7 |
| API (`apps/api`) | Render web service | 1c-2g | $25 |
| PostgreSQL 16 + PostGIS | Render Postgres | 0.5c-1g, 10 GB | $19 + $3 storage |
| Published price files (Parquet) | Cloudflare R2 bucket `procedurescout-prices` | pay as you go | first 10 GB free, then $0.015/GB |
| National downloads | GitHub Actions (public repository, D-049) | standard runners | free |

Everything Render runs is described in `render.yaml` (a Render "Blueprint").
Render documents PostGIS as available on PostgreSQL 13 and later.

## How the pieces connect

- The **website** calls the API at `/api/...`. `API_URL` is the API's private
  Render address (`host:port`); the website adds `http://`.
- The **API** connects to PostgreSQL as the restricted role `ps_api`, which can read
  published data only (CLAUDE.md rule 7). On Render it gets the owner
  `DATABASE_URL` plus `PS_API_PASSWORD` and builds its own `ps_api` connection
  (`settings.py`). The owner address is used only by the pre-deploy step.
- **Before each deploy**, `scripts/prod_db_setup.py` enables PostGIS and creates
  or updates the `ps_api` role (safe to repeat), then `alembic upgrade head` runs.
- The **API reads prices** straight from R2 with DuckDB's httpfs extension
  (`object_store.S3Store`), fetching only the parts of each file a search needs.
  The extension is installed at build time into `.duckdb_extensions`
  (`scripts/install_duckdb_extensions.py`), because Render keeps only the project
  folder between build and run. The API's R2 key is **read-only**.
- The **provider portal** (D-050) connects as its own role `ps_portal` (password `PS_PORTAL_PASSWORD`, generated by Render), which can write provider pages, reviews and counts only. `PORTAL_SECRET` (generated) keys reviewer fingerprints; `SITE_URL` is the public address used in emailed links. Until an email service is chosen (Q26), sign-in and review emails wait in `prov.outbox`, so providers can't sign in on the hosted site yet.
- The **GitHub download runs** stage prices in PostgreSQL and publish Parquet to
  R2 with a separate R2 key that can write (`PRICE_STORE_*` secrets in GitHub).

## Sign-up steps (with Cooper, when ready)

1. Cloudflare: create an account, turn on R2, and create the bucket
   `procedurescout-prices`. Create two R2 API tokens: "Object Read" for the API
   and "Object Read & Write" for GitHub.
2. Render: create an account, choose **New → Blueprint**, pick the GitHub
   repository and approve `render.yaml`. Enter `PRICE_STORE_ENDPOINT`
   (`https://<account id>.r2.cloudflarestorage.com`), the read-only key id and
   secret, and `NEXT_PUBLIC_SITE_URL`.
3. GitHub: add the read-and-write R2 key and the database's external address as
   Actions secrets.
4. Check on the hosted site: `/healthz`, a search, the robots file and that the
   preview label is gone.
